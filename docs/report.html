گزارش کامل مدل‌ها و تغییرات مدیریت پروژه

این گزارش، تغییرات انجام‌شده برای افزودن مدیریت پروژه، اسپرینت و وظایف به سامانه Karnex را مستند می‌کند. در این سند مشخص است هر مدل چه داده‌ای ذخیره می‌کند، با چه مدل‌هایی ارتباط دارد و داده‌های نمونه چه مواردی هستند.

۱. معماری پیاده‌سازی

Web Controller → MediatR → Application Features → IUnitOfWork → EF Core → SQL Server
  • Controllerها نازک شده‌اند و تنها درخواست HTTP را با Mediator.Send به Feature می‌فرستند.
  • منطق دریافت، اعتبارسنجی ارتباط‌ها و ذخیره داده در Application/Features قرار دارد.
  • Entityها در Domain، تنظیم روابط در Infrastructure و DTOها در Application نگهداری می‌شوند.

۲. مدل‌ها و داده‌های ذخیره‌شونده

Project — پروژه

فیلدنوعداده ذخیره‌شونده
Idintشناسه یکتا
Keystringکلید یکتا مانند WEB یا APP؛ مبنای کلید وظایف
Name و Descriptionstringنام و شرح پروژه
TypeenumScrum، Kanban یا Basic
StatusenumActive، Archived یا Paused
PrivacyenumPrivate یا Public
Icon و Colorstringاطلاعات نمایشی فرانت
StartDate و EndDateDateTime?بازه زمانی پروژه
Created، CreatedBy، lastModified، lastModifiedByAuditاطلاعات ایجاد و آخرین تغییر

هر پروژه چند عضو، چند اسپرینت و چند وظیفه دارد. درصد پیشرفت ستون مجزا ندارد و در خروجی API از نسبت وظایف Done به کل وظایف محاسبه می‌شود.

ProjectMember — عضو پروژه

فیلدداده ذخیره‌شونده
ProjectIdارجاع به پروژه
UserIdشناسه کاربر عضو
Roleنقش کاربر در پروژه، مانند Project Manager یا Developer

ترکیب ProjectId و UserId یکتا است؛ یک کاربر نمی‌تواند دوبار عضو یک پروژه شود.

Sprint — اسپرینت

فیلدداده ذخیره‌شونده
ProjectIdپروژه مالک اسپرینت
Name و Goalنام و هدف اسپرینت
StatusPlanned، Active یا Completed
StartDate و EndDateتاریخ آغاز و پایان

WorkItem — وظیفه

فیلدداده ذخیره‌شونده
ProjectIdپروژه اجباری وظیفه
SprintIdاسپرینت اختیاری وظیفه
ParentIdارجاع به Epic یا وظیفه والد
Keyکلید نمایشی مانند WEB-2؛ در هر پروژه یکتا
Title و Descriptionعنوان و شرح کار
TypeEpic، Story، Task، Bug یا Subtask
StatusTodo، InProgress، Review یا Done
PriorityLowest، Low، Medium، High یا Highest
AssigneeId و ReporterIdمسئول انجام و گزارش‌دهنده
StoryPointsبرآورد اختیاری پیچیدگی
DueDate و CompletedAtمهلت انجام و زمان تکمیل

حذف WorkItem نرم است؛ یعنی IsDelete تغییر می‌کند و داده برای گزارش یا بازیابی باقی می‌ماند.

مدل‌های وابسته به WorkItem

مدلداده ذخیره‌شونده
WorkItemLabelWorkItemId، نام و رنگ برچسب
WorkItemCommentWorkItemId، AuthorId، متن نظر و اطلاعات Audit
WorkItemAttachmentWorkItemId، نام فایل، URL، نوع محتوا، حجم و اطلاعات Audit
Attachment فقط متادیتای فایل را ذخیره می‌کند. آپلود و نگهداری فیزیکی فایل هنوز پیاده‌سازی نشده است.

۳. روابط داده

Project 1 ─── * ProjectMember
Project 1 ─── * Sprint
Project 1 ─── * WorkItem
Sprint  1 ─── * WorkItem
WorkItem 1 ── * WorkItem (Subtask)
WorkItem 1 ── * Label / Comment / Attachment

حذف دیتابیسی پروژه، اسپرینت‌ها و اعضای وابسته را حذف می‌کند. حذف اسپرینت، ارجاع SprintId وظایف را null می‌کند. WorkItem و Project از الگوی حذف نرم استفاده می‌کنند.

۴. APIهای اضافه‌شده

۵. Seed Data

در GenerateFakeData.SeedDataAsync، Seed فقط زمانی اجرا می‌شود که جدول Projects خالی باشد؛ بنابراین داده تکراری ایجاد نمی‌شود.

پروژه نمونهمحتوا
WEB — بازطراحی وب‌سایتدو عضو، یک اسپرینت فعال، Epic احراز هویت، وظایف ورود و ثبت‌نام، باگ جستجو، برچسب، نظر و پیوست نمونه
APP — اپلیکیشن موبایلیک عضو، یک اسپرینت فعال و دو وظیفه API و تست
CRM — سیستم مدیریت مشتریاندو وظیفه در وضعیت Done و Review
با اعمال migration و اجرای بک‌اند، seedها خودکار اجرا می‌شوند.

۶. اتصال داشبورد

فایل frontend/src/lib/karnex-api.ts ایجاد شد. داشبورد هم‌زمان آمار، وظایف، پروژه‌ها و اسپرینت‌ها را از API می‌گیرد. کارت‌های آمار، وظایف، پروژه‌های فعال، نمودار پروژه‌ها و اسپرینت‌های فعال داده واقعی دارند. فعالیت‌ها، جلسات و یادآورها هنوز Mock هستند.

GET /api/tasks/dashboard-stats

GET /api/sprints

۷. راه‌اندازی

dotnet-ef database update --project src\Infrastructure\Infrastructure.csproj --startup-project src\Web\Web.csproj --context ApplicationDbContext

آدرس پیش‌فرض API در فرانت http://localhost:21547 است. در صورت نیاز، در فایل .env فرانت مقدار VITE_API_URL را تنظیم کنید. CORS برای پورت‌های 3000، 5173 و 4200 فعال شده است.

۸. گام‌های پیشنهادی بعدی

  • افزودن Authorize و کنترل دسترسی بر اساس عضویت پروژه.
  • ساخت API اعضا، فعالیت‌ها، جلسات و یادآورها.
  • پیاده‌سازی آپلود واقعی فایل با MinIO یا Azure Blob.
  • افزودن FluentValidation برای Commandها.
  • اتصال Board، Backlog و Task Detail به API.
